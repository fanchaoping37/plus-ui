## 1. 已确认决策

1. 采用 plus-ui 6.X-Vue 作为唯一前端基础，不另起 Vue/React 工程，不改写其登录、布局、权限、菜单、组件基础设施。
2. Radius 业务只提交到 plus-ui 的 `develop` 分支；保留 `6.X-Vue` 作为上游同步基线。
3. AAA 前端 API 以 Radius-Vue-Plus 实际 Controller 和 DTO 为唯一接口依据，不复用上游 RuoYi 业务接口作为 AAA 业务接口。
4. AAA 用户是独立于后台 sys_user 的 RADIUS 用户主体；PAP 密码、EAP-MSCHAPv2 NT-Hash、上游运营商账号密码必须分离。
5. NAS Shared Secret、上游 RADIUS Server Shared Secret 和上游用户凭据分别管理，绝不在一个表单或一个 API 中混用。
6. 所有敏感请求必须关闭 plus-ui request.ts 默认的重复提交 session 缓存；个人信息解密只允许按字段授权并要求填写原因。
7. 前端只管理控制面配置和审计；RADIUS Access/Accounting/CoA/Portal/MAC-Trigger 数据面仍由后端处理。
8. 父菜单只在至少一个子菜单有权限时显示，子菜单逐项按后端 permission code 过滤。
9. 当前后端未暴露的接口不在前端伪造，先登记为集成阻塞，等后端接口契约明确后再补页面。

- 新增 `src/api/aaa/index.ts`，覆盖当前后端用户、NAS、用户组/标签/设备、Provider/Policy、上游凭据/Secret/Dynamic Authorization、审计、复核、Tenant Context API。
- 新增 AAA 用户、NAS、用户组/策略、认证 Provider/Policy、上游 RADIUS、安全审计页面。
- 用户管理覆盖独立 PAP、EAP-MSCHAPv2、上游用户凭据与个人信息加密/按字段授权解密。
- NAS 页面覆盖设备创建、来源地址集合编辑、Portal Profile 引用、Message-Authenticator 策略、状态和 Secret 轮换/生成 UI；地址 byte[] Base64 解码兼容；数值 ID 未由后端返回时相关操作禁用。
- Provider/Policy 页面支持草稿创建、编辑、废弃、发布和 Policy 回滚；编辑时按内容 SHA 做乐观锁；由于无 Provider 配置读取 API，编辑者必须输入完整新 JSON。
- 上游动态授权来源支持创建、编辑、启停、验证和审计；上游 Server Secret 只按 opaque reference 手动管理。
- Navbar 增加 Tenant Context selector，切换成功后整页刷新以重新加载权限和动态菜单；新增 superadmin 租户创建和管理员授权页面。
- 动态路由权限过滤改为递归处理嵌套菜单。
- 更新 Radius AAA 产品标题、package metadata 和 README。
- FreeRADIUS 对照已写入前端架构基线：前端不参与 Access-Request/Challenge、EAP/PEAP、MPPE key 生成；仅管理控制面，协议由后端处理。
