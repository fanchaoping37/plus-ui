## 1. 文档效力与分支约定

- 本文是 Radius AAA 前端的唯一有效架构与开发状态文档。
- `6.X-Vue` 是保留的 plus-ui 上游基础分支；不得直接在该分支开发 Radius 业务。
- `develop` 从 `6.X-Vue` 的提交 `8f681f3c758cb0fdaaab13f8ba8d51b50c8acfe1` 创建，是 Radius AAA 前端唯一开发分支。
- 不把上游 RuoYi-Vue-Plus 业务接口误认为 Radius-Vue-Plus AAA API；所有 AAA 接口以后端 `develop` 分支实际 Controller、DTO、权限和响应类型为准。
- 前端仅负责 AAA 管理控制面，不处理 RADIUS UDP 报文，不终止 EAP/PEAP，不生成 Access-Accept，也不直接访问 NAS/上游 RADIUS UDP 端口。

状态定义：
- **已实现（静态代码）**：前端页面、API wrapper 和路由代码已提交，不代表后端联调通过。
- **部分实现**：页面或 API 只覆盖后端部分操作，或被后端 API 契约阻塞。
- **后端缺口**：后端当前没有对应管理 API；前端不得自行伪造接口。
- **待验证**：尚未运行构建、类型检查、Lint、浏览器或 API 联调。

- `src/api/aaa/index.ts`：AAA 控制面 API、DTO 和请求类型。
- `src/views/aaa/tenants`：系统超级管理员创建租户和授权租户管理员。

- `src/views/aaa/nas`：NAS、来源地址、Portal Profile 引用、Message-Authenticator、Shared Secret。
- `src/views/aaa/policy`：用户组、标签、终端设备。
- `src/views/aaa/authentication`：认证 Provider / Policy 版本草稿与发布。
- `src/views/aaa/upstream`：上游 RADIUS Server Secret 引用和 RFC 5176 上游动态授权来源。
- `src/views/aaa/audit`：安全审计、CoA 和动态授权人工复核。
- `src/router/index.ts`：AAA 导航路由；每个子路由绑定后端 permission code。
- `src/store/modules/permission.ts`：递归过滤父子菜单权限，父菜单仅在至少一个子项授权时显示；无权限定义的叶子路由仍保持拒绝，不因递归改造意外开放。
- `src/layout/components/Navbar.vue`：租户上下文切换。

## 5. API 与数据安全约定

1. 所有 AAA 数据都在后端登录会话的当前 Tenant 上下文内操作。前端不能在普通 AAA 请求中自行提交 Tenant UUID 来决定数据归属。
2. 切换租户必须调用后端 `PUT /system/tenant/context/{tenantUuid}`，然后刷新页面，重新加载用户信息、动态菜单和权限。
3. NAS Shared Secret、上游 RADIUS Server Secret、AAA 用户 PAP 密码、EAP-MSCHAPv2 密码、上游运营商账号密码是不同安全域，页面和 API 不得合并成一个“密码”字段。
4. 所有凭据设置、轮换、PII 保存和解密请求设置 Axios `repeatSubmit: false`，绕过 plus-ui 默认重复提交请求体缓存，避免密码、Secret 和个人信息进入 sessionStorage。
5. 页面关闭时清空敏感字段；一次性生成的 NAS Secret 只展示本次响应，用户关闭后清除。
6. 个人信息默认只读取字段是否存在；解密需要单独权限、明确勾选字段和解密原因。
7. Provider JSON 只允许保存 secret-reference 标识，不能内嵌 password/token/private key/authorization 等秘密值。上游 RADIUS Provider 使用后端严格 schema：numeric serverHost、serverPort、serverSecretRef、userCredentialAlias、authenticationMode、username template 和显式组合认证开关。
8. 不记录前端凭据请求正文，不在页面中 console.log Secret 或解密后的个人信息。
9. RADIUS 协议 Secret 不能通过前端 API 暴露已存储明文；仅允许创建/轮换响应按后端契约一次性返回。

## 6. FreeRADIUS 流程与协议边界对照

| 层次 | FreeRADIUS 3.2.x 常见结构 | Radius 项目职责 |
|---|---|---|
| 管理控制面 | 主要通过配置文件、模块配置和 SQL/REST 后端组织，不由本前端承担 RADIUS 数据面 | 本前端负责多租户用户、NAS、Provider、Policy、凭据引用、授权条件和审计 |
| Access | RADIUS Access-Request / Accept / Reject / Challenge | 仅由 Radius-Vue-Plus Netty UDP 后端处理；浏览器不构造 RADIUS 报文 |
| EAP/PEAP | EAP 模块推进外层 TLS 和内层认证，多轮 Access-Challenge | 后端 PEAPv0 Dispatcher、TLS engine、Phase 2 和 Crypto-Binding 处理 |
| Inner auth | FreeRADIUS PEAP 常见内层 EAP-MSCHAPv2；需区分 EAP-MSCHAPv2 与普通 MS-CHAP 模块 | 前端设置独立 EAP-MSCHAPv2 密码；后端派生/存储 NT-Hash 并运行 inner EAP |
| Authorization | EAP 成功不等于授权；由后续策略模块完成 | 前端配置用户组、标签、认证 Provider/Policy；后端完成授权、Grant、Quota |
| Final Access-Accept | 最终响应可携带 MS-MPPE-Recv-Key / MS-MPPE-Send-Key | 仅后端按 RADIUS/PEAP 规范构造和签名响应 |
| Dynamic Authorization | RFC 5176 CoA / Disconnect | 前端只管理上游可信来源和人工复核；UDP 3799 收发由后端处理 |
| Accounting | Accounting Start / Interim / Stop 与 session 状态 | 当前后端数据面已有 accounting 处理，但尚无完整管理查询 Controller，前端暂不虚构 session 页面 |

FreeRADIUS PEAP 教程建议内层 EAP-MSCHAPv2，并说明它与普通 MS-CHAP 模块不同；成功流程通过多轮 Access-Challenge 推进，最终 Access-Accept 携带 MPPE key 属性。前端管理页面不改变上述 RADIUS/EAP/PEAP wire protocol。

## 7. 当前明确的后端集成阻塞

### 7.1 NAS 列表标识不匹配

- 后端 `GET /aaa/nas` 返回领域 `NasDevice`，其中包含 UUID `businessId`，但不包含数据库数值主键 `id`。
- NAS 状态、地址、Message-Authenticator、Shared Secret 变更接口却使用 `/{nasDeviceId}`，参数类型是 `long`。
- 因此前端不能安全地从 `businessId` 推导出 `nasDeviceId`；相关变更按钮已禁用并提示契约缺口，不会把 UUID 强转为数字或发送 0。
- 后端需提供包含数值 `id` 的 NAS 管理投影，或统一将这些管理接口改为 UUID businessId。

### 7.2 其他管理 API 缺口

- Provider 草稿列表不返回原始 configuration，后端没有按版本读取配置正文的 GET API；编辑 UI 只能要求管理员输入完整 JSON，并以 `contentSha256` 做乐观锁。
- 上游 Server Secret reference API 没有列表/读取接口；前端按 referenceId 手动创建、轮换或停用，不能展示服务端完整引用清单。
- 当前后端没有 AAA session/accounting 管理查询 Controller；没有可用接口时不创建在线会话、Accounting 记录或计费报表假页面。
- 当前后端没有 Vendor Profile、Portal Client Message Profile、MAC-Trigger Profile 的完整管理 Controller；NAS 页面只绑定已存在的 profile ID/version，不伪造 profile CRUD。
- 当前后端没有 Portal / MAC-Trigger 管理控制面 Controller；50100/2000 和 Portal/NAS/RADIUS 流程仍由后端协议处理，前端暂不假造配置 API。
